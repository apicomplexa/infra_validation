## Что осталось сделать

### 1. Исправления по рецензии критика (одобрены пользователем)

Каждое изменение — отдельный коммит, свой `docs/changes/2026-10-30-*.md` (по-русски:
что было не так, таблица «что изменилось»), регрессия явно проверяет ожидаемые
различия, остальные сравнения не ослаблять.

**ИЗМЕНЕНИЕ 1 — подсчёт и «Вид?» (все категории)**

- (a) **B1: одна вывеска, записанная дважды, — один объект в итогах.** Взаимные пары
  relink: запись A (только 2GIS) получает OSM от двойника B, а B — 2GIS от A.
  Проверено: общепит 34 пары, табак 65, алкоголь 3 (по `results/*_objects.csv`,
  колонки `osm_link_from` / `gis_link_from`). Брать компоненты связности relink-связей
  (на случай цепочек); для v4 — также записи, которые сверка ЕГАИС уже считает одной
  лавкой (`entity` licmatch), и сообщить, сколько это добавляет. Вердикты и «Основания»
  по записям не меняются; добавить колонку «Объект (склеен)» в выдачу и выходы; итоги
  считают склеенные объекты и рядом показывают число записей; проверить, что записи
  одного склеенного объекта никогда не расходятся в «Подтверждено». Таблица до/после
  по городам и категориям (объекты, подтверждено, %). Это сдвигает уже выданные цифры
  общепита (803/1141, 373/467, 50/80) — так и написать.
- (b) **`kind.vote_identity: [strong]`** во всех категориях: слабые находки (запись
  досталась соседу) больше не голосуют за «Вид?». Убрать это отклонение из config,
  `config/README.md`, `docs/ARCHITECTURE.md`; посчитать изменения «Общепит?» /
  «Алкоголь?» / «Табак?» по переходам значений.

**ИЗМЕНЕНИЕ 2 — алкоголь и табак**

- **S2:** в режиме v4 проверка имени для алкоголя должна сверять и название заведения
  из текста помещения в `outlet_address` (holder + venue, как в общепите). Примеры
  ошибочно слабых: «Старое место», «Кушать подано», «Почтовая контора 1786 г.»,
  «Миндаль», «кафе Шафран». Сейчас на месте (on-trade) 70 из 81 своих действующих
  слабые, на вынос — 51 из 269. Отчитаться strong/weak до/после по off/on-trade.
  `licence_status` / `licence_no` не меняются, паритет лицензий v4 точный.
- **S3:** словарь «Алкоголь?» в config: убрать ресторан/банкет из «да»; границы слов
  у стемов «нет» (`почт` → «Почтовая контора»); `(?<!без)алкогол`.
- **N1:** в сводке алкоголя — итоги по типам подрядчика (Direct 179 / Inferred 766)
  рядом с подтверждёнными, как у табака.
- **N3:** в табачной книге переименовать колонки ЕГАИС, чтобы читались как
  АЛКОГОЛЬНАЯ лицензия («Алкогольная лицензия: статус»).
- **N4:** фраза в легенде алкоголя: большинство записей только в OSM (922 из 945 —
  посчитать из данных), поэтому 0 — чаще нет провайдера, а не нет лавки.

Затем `pixi run lint`, `pixi run test`, `pixi run workflow`.

## Решения пользователя (обязательны)

- Новый репозиторий; только Linux; отчёты только на русском; `licmatch` в `packages/`.
- Алкоголь: лицензия ЕГАИС засчитывается в «Подтверждено» только при совпадении имени
  (прямо, известный алиас, выученная пара с leave-one-out); по адресу / общей
  вывеске — слабая.
- До финальных XLSX по алкоголю и табаку конвейеры работают на v4 через адаптер.
- Агентов можно запускать; модель выбирать по задаче (Opus — архитектура и сложные
  правила, Sonnet — механический перенос).
