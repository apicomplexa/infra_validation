# 2026-10-30: место Overture из одного Foursquare и колонка «Общепит?»

Первое изменение результата после переноса. До него конвейер воспроизводил
архив (`infrastructure_2026`, тег `archive-2026-10-30`) один к одному.
Исправлены две ошибки архива. Обе противоречат его собственной описанной
методике, поэтому это исправления, а не новые правила.

## 1. Место Overture, собранное только из Foursquare, засчитывалось как второй источник

**Как задумано.** Методика архива (CLAUDE.md, раздел «Final delivery»;
легенда «Подтверждения»): «Место Overture, собранное только из Foursquare,
засчитывается как Foursquare, а не как второй источник». Такое место — это
та же запись Foursquare, пересказанная агрегатором. Засчитывать её должна
прямая проверка FSQ по своему правилу свежести.

**Что было.** `final_confirm.decide` проверял
`ov_dataset.lower() == "foursquare"`. Overture пишет в поле не один набор, а
всю цепочку: `Foursquare|Overture`, `meta|Overture`, `AllThePlaces|Overture`.
Строка `"foursquare"` не встречается ни разу, поэтому условие не срабатывало
никогда. Каждое такое место считалось отдельным источником «Overture», хотя
у всех затронутых объектов та же запись уже засчитана как «Foursquare».

**Что стало.** Сравниваются наборы, а не строка: набор Overture не
засчитывается, если кроме самого Overture в нём есть только Foursquare.
`config.yaml`:

```yaml
exclude:
  - {source: overture, only: [foursquare], ignore: [overture], sep: "|"}
```

Строка Overture при этом молча исключается: не засчитана и не попадает в
«Основания» после « || », потому что это не отдельная находка. Записи,
доставшиеся соседнему объекту (`identity = weak`), по-прежнему выводятся после
« || », как и раньше. Колонки `ov_*` и строка «Найдено в Overture» в «Итогах»
не меняются: место по-прежнему найдено, оно просто не считается вторым
источником.

## 2. Колонка «Общепит?» поставлялась пустой

**Как задумано.** «Общепит?» — третья колонка спереди: да / нет /
противоречие / автомат / нет данных, с пояснением в «Общепит: основания».

**Что было.** `final_confirm.write_xlsx` записывал заголовок всех трёх
передних колонок, а значения — только первых двух (цикл заполнял колонки 1–2).
Во всех трёх поставленных файлах колонка пуста. Пояснения «Общепит: основания»
при этом заполнялись.

**Что стало.** Колонка заполнена во всех строках значением `food` объекта.

## Проверка

`tests/regression/test_catering_parity.py` по-прежнему сравнивает с эталоном
всё, кроме этих двух мест, а сами изменения проверяет явно:

- различия по `src_overture`, `n_sources`, `sources`, `reasons` есть ровно у
  21 перечисленного объекта (`OVERTURE_FSQ_ONLY`). У каждого `n_sources`
  уменьшился ровно на 1, «Overture» убран из «Источников», пункт Overture
  убран из «Оснований»; `confirmed` совпадает у всех 1 688 объектов;
- на листе `data` «Общепит?» в эталоне пуст, а у нас равен `food` объекта в
  каждой строке. Три ячейки исправления 1 отличаются только в строках этих
  объектов и равны решённым значениям. Все прочие ячейки и «Итоги» совпадают
  с эталоном точно.
