# 2026-11-25. Метрики валидации на текущей базе; отчёт руководителю собирается из неё

Вердикты конвейера не менялись: ни одна книга, ни база, ни «Подтверждено» не
сдвинулись. Пересчитаны оценки качества, которые до сих пор относились к
прогону 2026-11-22, и выдача руководителю теперь собирается так, что все её
числа читаются из одних и тех же файлов.

## Что пересчитано

| Оценка | Было | Стало |
|---|---|---|
| Существование, выборка B (methodology §8) | вердикты 2026-11-22 | те же метки аудитора и веса, вердикты текущего прогона и «В базу» единой базы (`pixi run calibration-current` → `results/finalest/calibration/{current,base}/`) |
| Сопоставление, слепые судьи (§9) | 260 решений прогона 2026-11-22, судьи Sonnet и Opus | 265 решений, заново отобранных из текущего прогона с политикой `config/finalest.yaml`; судьи `gpt-6.2-sol` и `gpt-6-luna` в Codex CLI (`results/finalest/internal_validity_v2/`) |

Метки выборки B от правил конвейера не зависят (существует ли объект,
работает ли, того ли вида), дизайн выборки фиксирован при отборе. С отбора
вердикт сменился у 9 из 435 объектов B, все в табаке.

Табак: два сетевых магазина, которые аудитор видит работающими, потеряли
подтверждение по правилу «закрытая карточка снимает «Найдено» подрядчика» —
наш запрос читает их карточку «Больше не работает». При 12 разрешённых
табачных объектах этого хватает, чтобы полнота упала до 0,73.

Яндекс: ложные отказы — сравнение имён без транслитерации («Marshall Grill» ↔
«Маршал гриль», «БрауМастер» ↔ «BrauMeister»). Каждая ошибка прочитана
(methodology §9.4). Из 7 объектов выборки с такой ошибкой у 5 остался один
источник, 4 из них стоят на листе «На ручную проверку». Конвейер не
исправлен: это изменение результатов, ему нужен свой разбор по объектам.

## Что изменилось в коде

- `internal_validity_sample.py`: `--overlay` (надстройка прогона поверх
  `config.yaml`), `--out` (первая выборка не трогается), страта
  `yandex_contractor_withdrawn`; решение по «Найдено» подрядчика берётся из
  свидетельств прогона, а не пересчитывается.
- `internal_validity_eval.py`: судьи и их файлы — из `judges.json` папки
  выборки; роль новой страты.
- `calibration_current.py` (новый, `pixi run calibration-current`).
- `build_deliverable.py`: раздел метрик README читается из
  `calibration/{base,current}/`, раздел сопоставления — из
  `internal_validity_v2/`; список `к_проверке_склейки_OSM_2GIS.xlsx`
  собирается из листов `quality` и текущей базы правилом страты
  `merge_unlike_names` (671 объект вместо 471 прежнего, где сравнивалась самая
  похожая пара); сборка отказывается, если метрики B посчитаны не на этой базе.
- `report_docx.py` (новый): «Методика/» (два docx со схемами Graphviz) и
  `сообщение_руководителю.txt`; все числа — из базы и файлов метрик.
- `pixi.toml`: `python-docx`; задача `calibration-current`.

Порядок сборки: `pixi run calibration-current` → `pixi run deliverable`.

Сводные таблицы обеих оценок (без названий и адресов) — `docs/validation/2026-11-25/`;

`resources/validation/2026-11-25/`, вне git (репозиторий публичный).
